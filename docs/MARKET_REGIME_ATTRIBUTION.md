# 市场阶段归因

市场阶段归因用于回答“策略收益主要发生在哪类基准环境”，不是预测器，也不是
新的交易信号。当前 protocol v1 固定参与 `experiment_input_id` 和结果哈希，避免
看到策略结果后再改阈值。

## 标签协议

对策略从日期 `t-1` 到 `t` 的日收益，标签只使用基准截至 `t-1` 的信息：

1. 取截至 `t-1` 的 60 个交易日收益窗口，需要 61 个基准价格观测。
2. 若历史不足，标签为 `insufficient_history`。
3. 若窗口末值相对窗口峰值回撤不高于 `-10%`，标签为 `stress`。
4. 否则，60 日收益不高于 `-2%` 为 `falling`，不低于 `2%` 为 `rising`。
5. 其余日期为 `sideways`。

压力优先于趋势。阈值是固定工程协议，不会根据本次策略收益、参数变体或执行
场景重新估计。60 日 ±2% 大致对应约 ±8% 的年化方向尺度，但这只是分类规则，
不是经济状态的唯一正确划分。

## 收益归因

每个 case 从第二行 NAV 开始计算：

```text
strategy_log_return[t] = log(NAV[t] / NAV[t-1])
benchmark_log_return[t] = log(B[t] / B[t-1])
excess_log_return[t] = strategy_log_return[t] - benchmark_log_return[t]
```

对数收益可以跨不连续的同类标签相加。所有阶段贡献之和必须分别等于策略和基准
从首行到末行的总对数收益，误差超过 `1e-12` 时实验失败。报告同时给出每个阶段
的复合收益，便于阅读；不同阶段的普通收益不能直接相加。

## 产物

每个 `cases/<case>/regime_attribution.csv` 包含：

- 收益日期和标签信息截止日。
- 阶段标签、60 日基准收益和窗口回撤。
- 策略、基准和超额的普通收益与对数收益。

`case.snapshot.json` 和根 `summary.json` 保存协议、计数、贡献和对账误差。日级
证据、case 摘要和协议都进入实验结果哈希。无基准策略不会猜测替代标的，而是
写入 `enabled=false` 和禁用原因。

test 汇总以单个 case 为统计单位，按“执行场景 × 参数变体 × 阶段”跨折给出最小、
最大和平均贡献。报告会声明测试窗口是否重叠；它不会把重叠日期拼成一条伪独立
收益序列，也不会输出 pooled performance estimate。

## 使用边界

- 标签来自基准，不读取策略持仓、成交或收益，也不进入策略决策。
- 归因是事后描述。它不能证明阶段可预测、收益可复制或策略具有统计显著性。
- 固定阈值未必适合所有资产和频率；修改协议应升级版本并重新生成全部实验。
- 基准选择、复权口径、数据修订和缺失值会直接改变标签，必须服从同一冻结数据
  lineage。
- 跨折比较可能共享训练期或测试日期，`case_count` 不能解释为独立样本量。
- 阶段表现不得用于回头选择参数；如未来把阶段作为特征，必须另建逐折训练、
  冻结和未触碰测试协议。
