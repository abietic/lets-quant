# 路线图

路线按风险递增，而不是按功能数量递增。只有上一阶段的验收门通过，才进入
下一阶段。

## M0：本地研究闭环

状态：已初步完成。

- 严格策略配置和合成示例数据。
- 固定权重、整手和次日执行参考回测。
- 费用、滑点、换手率、暴露和最大回撤约束。
- 基准比较、人工订单建议和可审计运行产物。
- 零运行时依赖的 Python 3.9 CLI 和单元测试。

验收标准：

- 所有测试通过。
- 相同输入可重复运行。
- `live` 配置、缺失价格和未知配置字段均被拒绝。
- 不存在任何券商网络调用。

## M1：真实数据研究

状态：核心工程闭环已初步完成，个人政策确认和首批真实数据运营验收待完成。

已实现：

- 严格研究范围配置：市场、允许资产、期限、基准、复权口径和最大回撤。
- `DailyBarsProvider` 接口、AKShare ETF 日线适配器和数据许可清单。
- content-addressed 原始快照，记录抓取时间、供应商版本、请求和数据权利声明。
- content-addressed 清洗数据集，记录 as-of、复权口径和全部输入哈希。
- 交易日历、上市/退市、停牌、分红、拆股和合股数据契约。
- 数据质量报告、`available_at <= as_of` 过滤和文件完整性校验。
- 停牌成交阻断，以及现金、静态目标权重和基准比较。

进入 M2 前仍需：

- 由用户确认候选 CN ETF 范围、期限、最大可承受亏损和实际交易费率。
- 用有明确来源和使用权的数据替换合成 fixture，保存首批真实原始快照。
- 为交易所日历、证券主数据和公司行动增加供应商快照，而不是长期手工维护。
- 对易修订字段采购或构建真正的 vintage 数据；当前历史行情快照不能反证
  供应商在过去时点返回过相同值。

验收标准：

- 任意历史日期只能读取当时可获得的信息。
- 数据修订不会静默覆盖旧回测。
- 策略收益能与无策略基线、固定配置和基准进行比较。

上述三项已由离线 fixture 和自动化测试覆盖；真实数据验收以首批供应商快照的
质量报告为准。

## M2：独立回测验证

状态：离线研究内核、参数稳定性协议、组合会计、事件驱动订单生命周期、第二
实现的 PIT 策略信号、清洗数据集停牌语义、未复权公司行动、非零初始持仓和
冻结证券主数据映射、市场阶段归因已完成；真实供应商主数据快照仍待接入。

已实现的前置能力：

- PIT-safe 策略契约、固定权重与透明动量过滤策略。
- 稳定 decision ID、目标权重和决策证据产物。
- 强制按时间隔离的 train/validation/test 实验协议。
- 费用、税费、滑点和成交延迟压力场景。
- 趋势、震荡、暴跌恢复、阶段切换和停牌等确定性合成市场。
- Sortino、Calmar、回撤持续时间、跟踪误差和信息比率。
- 显式会计账本、公司行动入账和每日现金/持仓/NAV 对账。
- 未复权拆并股跨越待执行订单时 fail closed，避免沿用失效数量。
- 多个向前滚动的 train/validation/test 时间折。
- 邻近回看周期、阈值和调仓频率参数变体，以及 test 段敏感性摘要。
- 明确禁止自动选取事后最优参数，并声明当前没有逐折模型拟合。
- 冻结 market-regime protocol v1：使用前一交易日基准历史标记上涨、下跌、
  震荡、压力和历史不足阶段，并按阶段核对策略、基准和超额对数收益贡献。
- 每个实验 case 保存逐日阶段证据；test 摘要按执行场景、参数变体和阶段跨折
  聚合，但不把重叠窗口当成独立样本，也不参与自动选参。
- 通用跨引擎候选契约，绑定参考 manifest、策略、价格、信号、NAV、成交和指标
  哈希。
- VectorBT 1.1.0 可选适配器，将卖出优先、现金缓冲、整手和成本规则 lowering
  后，由独立组合引擎复核订单记录、共享现金、持仓和 NAV。
- RQAlpha 6.3.0 可选适配器，用仓库冻结日线驱动原生事件循环和撮合，复核订单
  受理、资金不足部分成交、撤余单、卖出、费用、账户和 NAV。
- RQAlpha adapter v6 默认从策略快照与 PIT 价格历史独立复算固定权重/动量决策、
  decision ID、目标整手、换手率和订单意图，不读取参考信号决定候选订单。
- VectorBT adapter v5 与 RQAlpha adapter v6 都能重新验证 M1 数据集身份、质量、
  OHLCV/停牌观测和价格哈希；VectorBT 走 adapter 拒绝，RQAlpha 股票走原生检查、
  ETF 等非股票走 adapter 提交前拒绝。
- VectorBT 通过同日订单前的回调 lowering 未复权现金分红与整股拆并股；RQAlpha
  通过原生账户路径处理，并由适配器读取现金/持仓状态独立核对。
- 两个适配器都会拒绝跨越未复权拆并股的冻结订单，避免提交已经过期的股数。
- 带原始/规范化哈希的初始持仓快照、初始持仓账本分录和首日 NAV 统一语义；
  VectorBT 通过回调注入，RQAlpha 使用原生账户初始化。
- 首日已有持仓遇到企业行动时，两个引擎都严格按“初始化 -> 行动 -> 订单”执行。
- 每个参考回测固化证券主数据，每个候选提交逐标的映射；清洗 RQAlpha 路径使用
  规范代码、交易所、资产类型和上市日期，裸价格只能显式回退到合成身份。
- 跨引擎候选 schema v7 将证券映射、策略信号、订单摘要、全局有序事件和逐项
  企业行动证据纳入哈希，严格核对决策、状态迁移、现金/数量变化、费用及
  规范化成交。
- 可选完整流动性矩阵和成交量比例压力；执行结果改变时整体 fail closed，但订单
  生命周期仍单独报告内部一致性，便于定位失败阶段。
- 日期轴、NAV、现金、持仓、逐笔成交和核心指标的严格差异报告；输入或候选漂移
  后 fail closed。

仍需实现：

- 为交易所日历、证券主数据和公司行动接入有权使用的供应商快照，替代手工辅助
  输入；当前只完成冻结、映射和对账契约。
- 对未来需要拟合的模型加入真正逐折训练；当前规则策略没有伪造训练步骤。

验收标准：

- 扣除费用后，核心结论不依赖单一回测引擎。
- 参数附近的小幅变化不会让结果从盈利跳到巨亏。
- 报告同时展示收益、回撤、换手率、容量、市场阶段贡献和失败阶段。

## M3：模拟盘和对账

状态：离线状态机、恢复语义和运营审计已完成，外部模拟柜台适配与在线真相源
恢复未实现。

已实现：

- 独立 `execution/paper.py`，不复用回测成交结果。
- 提交、确认、部分成交、完整成交、拒单和撤单状态机。
- 事件 ID、客户订单 ID 和成交 ID 幂等，柜台订单 ID 全局唯一，冲突内容
  fail closed。
- 原子状态快照、内容哈希、重启恢复、账户重建及事件历史回放对账。
- 资金不足、持仓不足、超额成交和非法状态迁移阻断。
- 严格、带时区的运营审计输入和带三重哈希的确定性报告。
- 行情过期、任务失败、风险冻结和活动订单老化告警。
- 按决策 ID 对比预期与实际成交数量、均价、费用、终态和延迟。
- 导入式外部账户快照契约，以及现金、持仓、订单和柜台订单号差异告警。
- fixture 明确降级为 `review_required`，不冒充券商恢复真相源。

仍需实现：

- 对接一个明确的外部模拟柜台，并以柜台查询结果作为恢复真相源。
- 验证外部快照来源、分页完整性和查询时效，而不是相信手工 `source_kind`。
- 增加通知投递、确认、静默和升级策略，使告警形成可运营闭环。

验收标准：

- 故障注入后没有重复订单。
- 重启后可以从券商/模拟柜台状态恢复，而不是相信本地缓存。
- 所有仓位差异都有告警和人工处理流程。

## M4：小资金人工确认

- 只生成待确认订单，不自动发送。
- 每次确认前重新读取账户、价格和风险限额。
- 设置策略资金上限和独立的一键停止开关。
- 向券商确认程序化交易权限、报备与接口要求。

## M5：自动执行

默认不进入。它需要单独的产品决策、合规确认和安全评审，不能通过增加一个
配置开关从 M4 顺手开启。
